# F4: pressure validation timing and failure evidence

[CI322](https://github.com/snailjayxxx/JixelLight/actions/runs/41005819209) completed with a real Windows failure. Its owned-image pressure GUI reached 45,110 ms against the existing 45,000 ms deadline in phase 16, before its exact export completed. Linux passed its native audit and macOS passed native and deployed-package audits, but the Windows package and later checks were skipped; the run was not accepted. The original Windows log, validation ZIP, failed report and audit rejection remain preserved at `evidence/ci-41005819209/terminal-failed-v1/receipt.json`. The failed report named 22 screenshots, including a failure capture, but none of those PNG files was present in the uploaded Windows ZIP; they cannot be recovered from that artifact.

The owned-image UI test now freezes the committed Erase processing plan and independently renders its reference while Undo, Redo and project reopening continue. It checks the entire plan again before queuing the actual export, during the full-resolution scope check and before comparing output pixels and ICC. Export and scope checks can overlap, but neither the independent reference nor the exact output comparison is omitted. All 22 captures and the end-to-end 45,000 ms deadline remain required. This validation scheduling change was exercised by CI323, which again exceeded the Windows deadline.

On a failed pressure validation, the driver now copies only partial screenshots whose known labels, private paths, dimensions, device scale and SHA-256 agree with the native report. Sony screenshots must remain controls-only crops. Invalid, conflicting or symbolic-link inputs are rejected, existing different files are preserved, and the report remains failed with an explicit partial-evidence record. Eight focused synthetic tests cover failure preservation and rejection cases. A separate controlled UI fault injection changed the frozen plan deliberately: the native process and driver actually exited 1, and the candidate preserved 19 verified partial screenshots. This does not recover the missing CI322 images.

## Formal Root validation

The formal Root app, pressure-input probe, export verifier and Core test binary were built serially from the tested source. Controlled CPU/Metal UI runs at 1× on opaque and transparent owned images completed in 6,289/6,443/6,122/6,328 ms; the corresponding 2× runs took 8,259/8,606/8,176/8,453 ms. Each retained all 22 captures, the 45-second deadline, pressure and eraser checks, stable frozen plan and exact PNG16/ICC comparison. Eight failure-evidence tests and workflow YAML parsing passed. An independent audit checked all 198 PNG files from the eight UI and two Sony runs for CRC, dimensions and hashes.

The public Sony ARW CPU/Metal pressure regressions completed the GUI in 10,403/10,369 ms and export plus independent reference in 34,169.067/36,184.029 ms. Each retained 32,947,264 source, histogram and waveform pixels, the shared 3 GiB reservation, and exact PNG16 pixels and ICC under the unchanged 60,000 ms GUI and 120,000 ms export/reference deadlines. Peak reservations were 1,716,323,360/1,720,467,584 bytes. The native Sony reports retain their original `passed=false` while external pixel verification is pending; both independent verifiers and complete drivers exited 0. These are the existing real-Sony pressure regressions, not separate zero-pressure tests.

The local reports carry the pre-commit source stamp `0f34e19`. Formal evidence is recorded at `evidence/F4-ci322-recovery-root-local-v1/receipt.json`.
