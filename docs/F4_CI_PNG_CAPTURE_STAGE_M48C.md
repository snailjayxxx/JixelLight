Its owned-image pressure GUI took 45,229 ms against the unchanged 45,000 ms limit; exact export and the Windows deployed-package check did not complete. Linux passed its native audit and macOS passed both native and deployed-package audits. The failed Windows validation ZIP contained all 22 reported partial screenshots, including the failure image. Original FULL logs, ZIPs and results are sealed at `evidence/ci-41015537079/terminal-failed-v1/receipt.json`; this run was not accepted. The report recorded 38 window grabs taking 17,780.0844 ms in total; this is an observation, not a proven complete cause of the timeout.

The owned-image pressure check now asks Qt for a faster lossless PNG compression setting and reports screenshot-save counts and timing. It still captures and hashes each original frame, requires all 22 screenshots and preserves the same pixel, color, scope and exact-export assertions and the 45-second end-to-end deadline. Four screenshots from the actual failed Windows artifact were each encoded with seven settings on this Mac: all 28 decodes preserved pixels and color space, and the chosen setting retained all non-image PNG chunks compared with the default. On this Mac those four encodes took 79.20 ms in total versus 137.16 ms with the default. That is not a Windows performance measurement, and only a new Windows CI run can establish whether the deadline is met.
