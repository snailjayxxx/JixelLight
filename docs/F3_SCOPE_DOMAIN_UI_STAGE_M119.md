# F3 Source / Working / Display scope selection — M119

This private UI/controller integration extends M115/M117/M118. It requires its own build, targeted/native checks, frozen full102 regression, expanded native closure and platform/package qualification. Those are pending at this snapshot. Main and protected PR15 remain unmerged.

The bilingual sticky scopes selector defaults to Display, with Source RGB and Working RGB available for all four plot modes. Source is decoded RGB before edits after the current geometry, not sensor/CFA data. Working is the established pre-output/perceptual boundary. Both use linear sRGB/D65 CPU reference statistics and retain1024 histogram/vertical plot levels. Display preserves the encoded-sRGB/pre-monitor defaults, GPU histogram path, original near-black/near-white thresholds and analysis-frame reuse. No raw decoder, output/render math, Develop settings/history or export is changed by the selector. Linear range labels explicitly mean all RGB<=0 / any RGB>=1; linear plots use Y/color-difference coordinates and clamp graph indices only.

Domain selection cancels pending producers and clears the old histogram/plot before submitting current-domain work. Histogram/plot deliveries are bound to domain and image revision; plots also retain mode/full-resolution checks. Encoded GPU packets are accepted only in Display. CPU/Metal preview presentation remains independent of linear analysis; preview linear work uses the prepared source/plan, while exact linear work takes original source plus view geometry. Returning to Display can count a prepared CPU reference without waiting for a new image revision. A separate preview-analysis job and fourth deferred-budget slot prevent it from borrowing the display renderer's retry state. The original eight-attempt/5s retry policy remains. Source changes/close cancel and destroy the extra job. Presentation-only selection has owner-thread/closing checks and handles owner deletion during its signals.

Four new controller cases are included in the existing `brush-scopes-scheduling` group (expected16 Qt rows including initialization/cleanup). They exercise live Source/Working/Display statistics and plots, unchanged image bytes/Develop/history/revisions, invalid/foreign-thread selection, stale domain and GPU rejection, blocked exact cancellation without blocking the GUI, exact-to-preview transitions, real brush budget exhaustion/recovery, deferred-work cancellation and owner destruction during selection. Existing CTest group count stays102.

The normal native App smoke adds three pointer/keyboard selector operations. Source/Working preview histograms compare all four1024-bin arrays and linear range counts against a separately rendered reference; current waveforms, unchanged prepared pixel fingerprints/Develop/history/image revision, cleared stale results and restored Display are required. Two domain screenshots are saved when requested, and `ui_scope_domains_passed` plus its predicates are included in the aggregate smoke acceptance. The original60s deadline and original checks remain. New snapshots/plots do not claim native-FP32 RAW decoding, sensor clipping or A7R VI real-shot validation.
