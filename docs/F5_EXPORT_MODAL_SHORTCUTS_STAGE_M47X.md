# F5 M4.7X: keep export settings keyboard focus

When a button in the modal Export Settings dialog had focus, application-wide `G` and `D` could switch the background workspace. The fix suppresses those two shortcuts while the dialog is visible and restores navigation after dismissal. Existing recipe-dialog isolation remains in place.

A controlled Qt QPA probe using current Root QML and the actual controller reproduced the background switch on both Continue and Cancel in offscreen and Cocoa. The original reports and real process failures are retained. A separately linked private application reproduced the same four failures after the original 14 shortcut-guide checks and actual menu navigation into batch export. The candidate's private application passed the existing 14 checks plus an export-dialog check in offscreen 1×/2× (3,934/4,597 ms) and Cocoa 1×/2× (4,074/4,758 ms) under the original 60,000 ms limit. It checked both buttons, unchanged photo/history/selection, no queued export, ordinary text entry in the filename template and restored Library/Develop shortcuts after Cancel. Two existing recipe-dialog runs retained all 34 cases in offscreen QClipboard and Cocoa fake-clipboard modes.

The private binary was compiled with pre-commit stamp `6f66955`; its QML and linked source are derived from published Root `008ffae`, with three candidate files changed in an isolated directory. The original baseline, four candidate reports, two recipe regressions, candidate source, binaries and independent 20/18 negative controls are sealed at `evidence/F5-export-modal-shortcuts-private-v1/receipt.json`. These are controlled QPA tests with owned pixels, not physical keyboard, native OS clipboard, actual package or whole-project acceptance.

Supplementary private selected-export evidence used the actual selected-export menu and controlled QPA button input with two owned 512×320 images. After the dialog captured the blue photo, the test changed selection through an internal controller API; the captured one-name preview stayed fixed. The Continue button was clicked and the folder choice was simulated by setting the dialog folder and delivering its acceptance signal. The actual export queue completed one job and created only the originally captured blue photo as PNG16. An independent PNG parser checked chunk CRCs, dimensions, alpha and sample colors, plus the embedded ICC bytes against the source. The probe process returned zero in 1,317 ms with all 13 checks true. Its first wrapper incorrectly required ten checks and therefore really exited one; that failure remains alongside the independent re-audit. The 35-file private evidence is sealed at `evidence/F5-selected-export-output-private-v2/receipt.json`. This is not a physical pointer/keyboard or native folder-picker test and is not formal Root or cross-platform acceptance.

The first supplemental archive captured its own still-empty collector log in one private-work copy; its completed original log is separately retained. The corrected v2 archive excludes the live log during collection and verifies the completed log during sealing.

A further controlled test opened the actual English “Export Current Photo” menu item and confirmed the single-photo dialog mode. With the pre-fix Root QML the two buttons leaked all four `G`/`D` combinations (probe exit 1, 1,091 ms). With the isolated candidate QML, offscreen and Cocoa each passed all eight records in 1,104/1,366 ms, including button focus isolation, Undo preservation, clicking Cancel, no export queued and restored `G`/`D` after closing. The three original reports and the baseline failure are sealed at `evidence/F5-current-export-menu-private-v1/receipt.json`. The app controller and menu were real, but input was controlled QPA rather than physical keyboard or pointer; this is private evidence only.

## Formal Root validation and limits

The actual Root application, pressure-input probe and export verifier were built serially with the pre-commit stamp `008ffae`. The 221 source files, tested binaries and the user's preferences remained unchanged during the tests. Four Root shortcut-guide runs (offscreen 1×/2× and Cocoa 1×/2×) passed 15 checks in 3,989/4,549/4,250/4,708 ms, preserving the 60,000 ms limit. They exercised both export buttons, filename-template text, unchanged photo/history/selection, no queued export and navigation after Cancel. Two recipe-dialog regressions retained all 34 checks in 3,610/3,725 ms using isolated offscreen QClipboard and Cocoa fake clipboard. These are controlled Qt QPA inputs, not physical keyboard or native-system clipboard tests.

On the public Sony RAW source, actual Root CPU/Metal pressure GUI runs completed in 10,280/9,955 ms; export plus independent reference took 34,262.647/33,483.327 ms. The source, histogram and waveform each covered 32,947,264 pixels; exact PNG16 pixels and ICC passed, along with the shared 3 GiB reservation and unchanged 60,000 ms GUI / 120,000 ms export-reference limits. The reservation is not process RSS. The build and reports are stamped with the pre-commit head, not the later commit.

The AFP network volume rejected one atomic file replacement while applying the candidate. The original failure, unmodified prior backups and partial changes are retained; a guarded recovery verified all 221 source hashes and wrote the remaining validator in place before the build. Local Root evidence is recorded at `evidence/F5-export-modal-shortcuts-root-local-v1/receipt.json`. Cross-platform tests for the new commit, deployed packages, physical input, native GPU brush, native FP32 RAW and completion of all F0–F6 remain pending or unproven.
