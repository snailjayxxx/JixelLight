# F4: coalesce burst brush-preview preparation

A sequence of tablet packets can arrive in one event-loop turn. Previously each accepted packet synchronously rebuilt and preflighted a preview, even though the live queue could render only the latest pending state. The controller now schedules one zero-delay callback for that turn and prepares the latest sampled state there. Every accepted position and pressure packet still enters the existing sampler immediately; separately timed packets can still produce separate previews. This is not a frame-rate limit.

Release or cancellation stops the pending callback. A successful older frame cannot cancel a newer scheduled frame, and the existing budget-exhaustion retry remains independent. The controller also stops the schedule timer during shutdown. A request already active or pending for the same gesture and sample is not submitted twice.

The sampler, brush document format, 4,096-dab single-stroke limit, 16,384-dab document limit, tile/frame work budgets and shared 3 GiB reservation are unchanged. The latest sample still commits if the pointer is released before its preview callback. Continuously varying subpixel jitter can still exhaust capacity and reject the whole stroke; the warning is not a commit guarantee.

## Local validation

The formal Root app and relevant test executables were rebuilt serially. The existing 69 CTest names remain; the registered live-controller case now includes six methods covering burst coalescing, older-frame ordering, shutdown with a pending timer, budget retry, continuous input, and the prior transient-state checks. All six selected registered cases passed, including all nine pressure-gesture methods, as did three existing geometry/low-pressure/eraser methods. Source, binaries and ordinary preferences remained unchanged during these checks.

A test-only QPA entry linked against the formal product controller delivered 7,001 synthetic updates on the actual canvas and committed one 3,503-dab stroke. The final pressure change was visible before release; pixel, Undo/Redo, zero-pressure and history checks passed on CPU at actual 1× opaque and Cocoa/Metal at actual 2× transparent, with six CRC-checked PNGs each. In one local burst, the prior controller took 4,419 ms and the current controller took 164 ms on CPU or 161 ms in the Metal-display run. These are single controlled observations, not a throughput guarantee or a physical tablet test. A separately timed 1 ms synthetic stream continued publishing previews during input.

Both retained 32,947,264 source, histogram and waveform pixels, the shared 3 GiB budget, exact PNG16/ICC and original 60,000/120,000 ms limits. The Sony runs are existing pressure regressions, not scheduler-specific or physical-tablet tests; their native reports retain the external-verification-pending state while the wrapper and independent verifier passed.
