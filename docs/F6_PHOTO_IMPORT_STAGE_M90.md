# F6 M90 — existing-source import commands

`photo.import` is registered with explicit desktop/session forms. The desktop accepts a native `source` path and derives the catalog key; offline sessions retain their required session-local `photo` alias plus `source`. The shared pure decoder validates exact fields/types, bounded nonempty source text, forbidden NUL and complete ASCII session IDs. Desktop native filenames retain their existing character semantics; session source/control-character rules remain strict. The registry does not read images, metadata or filesystem facts. These are existing-source registration operations, without source-file writes or copying.

Desktop `executeCommand`, legacy single/batch import, the Add file chooser, drag/drop and startup use the same decoded request and existing importer. Batch notifications remain deferred, duplicate canonical files are refused, an existing current photo/history/selection stays selected, and an empty batch selects its first successful source. Existing partial-success counts, RAW stored-as-shot initialization, catalog persistence, asynchronous metadata/identity jobs and error messages remain. Thread/destruction guards reject new dispatcher/legacy-batch requests. Internal Copy/Move publication keeps its established paths. Existing `import_file` traces add a canonical absolute-source command and version key without a second event.

Two Core cases check normal single/batch registration, duplicate/missing/invalid/nested command refusal, history/source-byte isolation, aggregate counts, one batch model notification, initial selection, a physically foreign thread and reusable close preflight. A session case checks the different identity forms, unchanged caller output, no source-context reads for malformed imports, complete ASCII-ID boundaries, native-path versus session control-character rules and registry/session schemas. The ordinary/installed CLI suite checks those forms and late invalid imports without publishing earlier planned outputs. The existing normal-App smoke now imports its owned undated PNG via public `photo.import` and requires acceptance plus a real catalog addition while retaining every previous UI/export check and the60-second deadline; startup continues through the batch path.
