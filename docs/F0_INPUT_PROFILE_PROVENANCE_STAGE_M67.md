# F0 — Effective input color profile provenance

Ordinary raster sources now retain the color interpretation used before conversion to linear ProPhoto RGB. A valid color space returned by the image decoder is recorded as `provided-profile`; a source without a usable decoded color space retains the existing sRGB assumption and records `assumed-srgb`. A provided color space can come from ICC or other supported image color metadata, so the UI does not claim that an embedded ICC chunk necessarily exists.

The source metadata includes a bounded, whitespace-normalized description and the SHA-256 of the effective input profile. The hash also describes the assumed sRGB profile when that policy applies; it is not a hash of an original file chunk. These facts survive the existing memory/disk-preview metadata paths and are available to diagnostics. The original file, pixel conversion, working profile, RAW decoder, engine version, output ICC and monitor presentation are unchanged.

The footer displays the current input profile or the explicit sRGB assumption in English and Chinese. A dedicated notification follows source metadata, photo selection and language changes. Before a full source arrives it displays a pending state, including when an older disk preview lacks these facts. Language changes do not request a new render. Profile descriptions are rendered as plain text because they originate in image metadata.

Two focused regression methods cover tagged Display P3 and untagged RGBA16 input, exact pre-existing working conversion, source-byte preservation, memory/disk metadata, asynchronous caption refresh, photo switching and language changes without render revision changes. The full434-step build and the two focused methods plus the existing real-DNG controller method pass (5 Qt results, zero failures/skips/blacklists,1667ms). The initial focused run retains two failed fixture expectations: whole-QImage object equality was replaced by exact complete RGBA16 row comparison plus the explicit working-space text check, and importing a second catalog item is followed by an explicit selection rather than assuming import changes selection. No production behavior or pixel tolerance is relaxed. A frozen full regression, exact native application checks and platform delivery remain pending at this implementation state. This stage does not implement soft proofing or claim completion of F0–F6.
