# F4: explicitly recover a completed brush prefix

An over-limit paint or erase gesture still refuses the full edit without changing the photo or history. When a previously accepted prefix can finish within the original capacity and render limits, the canvas shows **Apply completed part** and **Discard**; these actions become available after the pointer is lifted. The end of the rejected gesture is not applied. Applying the prefix creates one ordinary stroke and one undo entry; discarding preserves the previous edit and redo branch.

The sampler retains a bounded checkpoint of the last finishable accepted prefix. Normal accepted input keeps its original sampling arithmetic. Recovery does not raise the 4,096-dab single-stroke limit, 16,384-dab document limit, tile/frame work limits or shared 3 GiB reservation, and does not add a document schema. Applying rechecks the original photo/source/geometry/edit context and existing admission checks. Invalid input or failed admission still refuses the edit.

New brush starts are blocked at both the canvas and controller while a valid choice is pending. Brush parameters, Clear and New layer stay disabled until the decision. Escape discards the offer and keeps the brush tool active; other edits or changes that invalidate its original context expire the offer. A regression first reproduced a direct-controller call silently replacing the decision, then verified all three public start routes preserve it. Its failure record remains in the private evidence.

This lets the user salvage a bounded prefix. It does not retain the rejected tail or fix complete continuously varying subpixel jitter. Physical tablet behavior has not been verified.
