# M107: Two compute workers on three-core hosts

The previous automatic CPU budget was `clamp(logical processors - 2, 1, 8)`: hosted three-core macOS processes therefore used one compute worker. Local qualification explicitly uses four. The normal CI workflow and its validators do not set that override, so their default execution path differs. This is configuration evidence from `ParallelRows::threadBudget`, not proof that worker count alone caused a particular timeout.

Automatic three-core allocation now uses two compute workers, retaining one core for UI work. Unknown/one/two-core hosts still use one; four-or-more retain their previous two-core reserve and eight-worker ceiling. Explicit `JIXELLIGHT_CPU_THREADS` parsing and1..32 limits, the shared bounded helper pool, memory/brush budgets and build process cap remain unchanged. This deliberately changes automatic scheduling on three-core hosts; it does not change per-pixel arithmetic or LibRaw's decoder configuration. No workflow override, deadline increase, missing context or tolerance change is introduced.

Diagnostic snapshots and large-source test evidence now record the effective compute budget. Raster tests retain their128-row independent reference and every complete pixel/ICC/source assertion, adding reference elapsed time and decoded-reference pixel/ICC hashes for paired observations.
