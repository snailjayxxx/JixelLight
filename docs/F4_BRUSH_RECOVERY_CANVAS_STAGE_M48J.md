# F4: require actual-canvas prefix recovery validation

M48I lets a user explicitly apply the last completed prefix of a refused brush gesture. Its controller methods passed three-platform CI330, while recovery-specific canvas checks were local test entries. M48J adds a dedicated validation entry to the real application and requires it in native CI and both actual deployed-package checks. Normal editing, sampling, brush controllers, QML, document formats and render code are unchanged.

Eight cases cover Paint and Erase, CPU and GPU presentation, and opaque and transparent owned RGBA64 images. Each injects controlled QPA stylus packets at unique, very close positions with alternating pressure. It requires the existing refusal and verifies the recovery actions are disabled while held, enabled after lift, and protected against replacement gestures, bracket keys and brush controls. Explicit application must create one bounded ordinary stroke and one Undo entry with a visible canvas change. Undo must restore pixels and history. A second refused gesture is discarded while the existing Redo branch remains unchanged; Redo restores the applied pixels. A third offer is dismissed with Escape, preserving the edit, brush tool and enabled controls.

Each case retains ten SHA-256/CRC-checked PNG captures: before, held, available, applied, undo, discard offer, discarded, redo, Escape offer and escaped. Reports retain isolated settings, actual QPA/backend/DPR, source hash, refusal packet counts, recovered dab count and explicit scope limits. The validator preserves verified partial captures and original reports/logs on failures, and refuses existing output paths. Twelve unit tests cover required behavior, false acceptance claims, capacity/deadline violations, missing or corrupted captures and overwrite refusal. Four application-level CLI checks reject orphan erase flags, mixed validation modes and positional sources.

## Formal local validation

The Root app was rebuilt serially from parent `224e0bb` plus the new smoke entry and registrations. Eight actual-canvas cases passed in 1,286–2,519 ms, using offscreen CPU at actual 1× in English and Cocoa/Metal at actual 2× in Chinese, with opaque and transparent images on both. All three stress gestures in every case were refused at packet 8,192; explicit recovery retained 4,096 dabs. All 80 captures passed independent PNG CRC, dimension and hash checks. The English and Chinese available-choice panels were visually inspected. Twelve validator unit tests and all four invalid CLI combinations passed.

The formal local receipt is `evidence/F4-recovery-canvas-root-local-v1/verified-v1/receipt.json` (360 files, 80 PNGs; SHA-256 `a2aba84bdb5badfeb14d16c94171ae5a1638e8647ca87e3e0deda0594d6547f8`). It binds 228 source files and the tested app binary, and records that only validation registration changed among the 225 parent sources. The first outer driver attempt was refused by the fresh-output guard because its log used the report's reserved filename prefix; it did not launch the app. That original failure is preserved and the corrected fresh-path run passed.

Existing 69 CTest names and all original native/package checks remain mandatory. The eight new package modes are additional to the original 29, for an expected total of 37. These additional owned-image cases retain the 60,000 ms recovery deadline; they do not replace or relax the original 45,000 ms pressure cases, Sony 60,000/120,000 ms limits, 32 Mi-pixel coverage, shared 3 GiB reservation, exact export/ICC, RAW, color or full-scope gates. Existing heavy regressions were already accepted for the unchanged product pipeline at CI330 and were not repeated locally for this validation-only change.

The new commit still requires complete three-platform and both deployed-package acceptance. These are simulated QPA input checks, not physical tablet or OS-activation verification. They deliberately reproduce the unresolved continuous unique-position pressure jitter refusal and do not retain the rejected tail, verify recovery-specific Sony behavior, introduce native GPU brush computation or establish native FP32 RAW decoding.
