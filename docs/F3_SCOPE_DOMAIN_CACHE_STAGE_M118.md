# F3 linear statistics and domain-aware result caches — M118

This private integration stage extends M115/M117. UI domain selection and controller delivery binding are still pending. No own frozen full102 or platform qualification is claimed at this snapshot.

`ScopeRequest` and `ScopePlotRequest` default to Display. Source and Working use distinct versioned result keys; unchanged Display requests retain their original keys, encoded counting rules, optional completed RGBA64 frame reuse and rendering path. Source keys include decoded pixel identity, input encoding/matrices, geometry and engine version, while ignoring edit/output intent. Working keys conservatively include the processing plan. Request revisions are delivery identity, not cache dependencies. No linear pixels enter or are read from the existing RGBA64-only analysis-frame cache; linear jobs stream bounded128-row outputs and retain only completed histogram/plot results under the existing result-cache budgets.

Source means decoded RGB before edits, converted to linear sRGB/D65 after the requested geometry; it is not sensor/CFA data. Working means the existing pre-output/perceptual boundary. Active Working brushes require the typed float admission, retaining32Mi source pixels/3GiB limits and retryable budget refusal. The prepared admission preserves validated viewport mapping and source-density spatial parameters; it never reapplies geometry. Full-resolution requests take original sources plus geometry, and preview Working requests take prepared sources plus their prepared plans. Both are one-use and keep output leases charged. The original display admission mode and estimates remain unchanged.

Linear histograms count1024 bins directly from finite FP32 samples. Linear waveform/parade use1024 linear levels; vectorscopes calculate linear Y/color-difference coordinates from signed/HDR RGB before clamping graph indices. Alpha is validated but does not weight channels, matching the established histogram policy. These coordinates and linear all-RGB<=0/any-RGB>=1 range counters must be labeled explicitly when the UI is connected. They are not encoded Cb/Cr or sensor clipping. Invalid/cancelled strips cannot publish partial results. Optional result caching never weakens brush admission or makes invalid plans cache hits.
