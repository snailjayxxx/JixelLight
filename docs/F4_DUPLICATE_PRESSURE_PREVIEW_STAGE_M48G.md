# F4: avoid redundant previews for repeated pressure packets

When a tablet repeatedly reports exactly the same position and pressure, the brush sampler's state is unchanged. Previously each packet still advanced the preview sequence and scheduled the same frame. In a controlled controller test, 40 identical packets produced two additional preview publications. The controller now skips those redundant updates while preserving a retry if the current preview has not been published. The comparison keeps positive and negative zero distinct; any changed position or pressure continues through the original sampler.

The preview queue checks whether the current gesture and sample are actually active or pending in its current cancellation epoch. A cancelled older request can still be running, so queue activity alone cannot prove that the new frame is scheduled. A regression test reproduced that missed-retry case against an intermediate implementation and verifies that the current implementation queues the new frame.

This change does not alter the brush document format, dab limits, pressure sampling or color calculations. It does not solve the separate case of continuously varying subpixel positions and pressure that can exhaust a stroke's capacity. A preview warning remains a mitigation, not a guarantee that a stroke can be committed.

## Local validation

The app and relevant test executables were rebuilt serially. The three registered live-preview methods passed, including unchanged-frame suppression, retry after a missing preview, cancellation epochs, pressure changes and a stationary peak. All nine registered pressure-gesture methods and three existing geometry/low-pressure/eraser tests passed. The original failing duplicate-preview and stale-queue observations are retained.

Controlled QPA stylus events were sent to the actual photo canvas through a test-only smoke entry linked against the formal product controller. CPU at 1× opaque and 2× transparent and Metal at actual 2× transparent each delivered 40 identical packets without another settled preview publication, while preserving the visible pressure pulse and Undo/Redo. Six screenshots per run passed SHA-256 and PNG CRC checks. These controlled events are not a physical tablet test.

These Sony runs are existing pressure regressions, not tests of duplicate packets on a physical pen.
